结论：可以接入，但只能作为“可选加速引擎”，不能直接替换当前所有Mod和整合包下载。

迅雷SDK基于P2SP，官方定位包含游戏更新、大文件和资源分发场景，因此方向是匹配的。[迅雷下载SDK文档](https://open.xunlei.com/doc)

### 当前适用范围

| 下载类型 | 现在能否使用 | 原因 |
|---|---:|---|
| Modrinth公开Mod | 可以 | URL公开、不需要额外header |
| GitHub公开Mod | 可以 | 通常是公开HTTPS URL |
| 大型resource pack/shader pack | 很适合试点 | 文件较大，更可能体现P2SP价值 |
| CurseForge Mod | 暂时不行 | 部分forgecdn下载需要`x-api-key` |
| RDI客户端整合包 | 暂时不行 | 当前下载需要CraftRDI账号的Bearer header |
| 私有或有权限控制的文件 | 不建议 | P2SP与受控分发存在安全及授权风险 |

### 主要技术限制

本地Java Desktop SDK支持Windows、macOS、Linux及Java8+，接入方式与当前Compose Desktop兼容：[README.md](/mnt/c/Users/calebxzhou/Downloads/xunlei-dlsdk-java-desktop/README.md:1)。

但我检查了[xl-dl-desktop-1.0.2.jar](/mnt/c/Users/calebxzhou/Downloads/xunlei-dlsdk-java-desktop/libs/xl-dl-desktop-1.0.2.jar)的public API，它只有：

- `createP2spTask(url, savePath, saveName)`
- start、stop、delete和progress查询
- concurrency、speed limit和upload控制
- dynamic link acceleration

Java`1.0.2`没有暴露官方native API中已有的：

- custom HTTP header
- batch task

这直接影响两个现有下载路径：

- CurseForge下载会按URL添加`x-api-key`：[ModService.kt](/mnt/c/users/calebxzhou/documents/coding/rdi5/common/net/src/main/kotlin/calebxzhou/rdi/common/service/ModService.kt:587)
- RDI整合包下载使用Bearer token：[RServer.kt](/mnt/c/users/calebxzhou/documents/coding/rdi5/client/ui/src/main/kotlin/calebxzhou/rdi/client/net/RServer.kt:151)

所以这两类文件目前不能交给该Java SDK。

### 加速收益判断

当前下载器本身已经支持：

- 多URL和mirror
- HTTP Range
- 16个分块worker
- resume和retry
- 每URL独立header
- SHA-1或CurseForge Murmur2校验
- 临时文件与atomic replace

相关入口在[FileDownloader.kt](/mnt/c/users/calebxzhou/documents/coding/rdi5/common/net/src/main/kotlin/calebxzhou/rdi/common/net/FileDownloader.kt:115)。

因此迅雷对几百KB到几MB的小Mod未必更快，task创建、登录和轮询开销甚至可能抵消收益。更适合大型整合包、resource pack、shader pack和大型Mod。实际提升必须A/B测试，不能直接采用官网营销数字。

### 推荐接入方式

不要把SDK塞进`common/net`，建议建立client-only模块：

```text
client/xunlei-download/
```

仅在满足以下条件时选择迅雷：

```text
公开HTTPS URL
没有custom header
文件建议≥16MiB
存在可信hash
用户启用了高速下载
SDK已经成功初始化和登录
```

执行流程应为：

```text
先尝试本地复用
  → 符合条件则使用迅雷下载到.part
  → SHA-1/Murmur2验证
  → atomic replace
  → 迅雷失败则删除.part并回退现有FileDownloader
```

不要让迅雷SDK跳过现有validator。例如Modrinth资源现在下载到staging文件、校验SHA-1后才替换目标文件：[ModrinthProjectDownloadService.kt](/mnt/c/users/calebxzhou/documents/coding/rdi5/client/ui/src/main/kotlin/calebxzhou/rdi/client/service/ModrinthProjectDownloadService.kt:48)。

### 上线前必须处理

- 不要把迅雷API Key放进launcher。README示例直接调用`getLoginToken(apiKey)`只适合试验；生产环境应由`server/master`持有API Key并签发短期login token。
- P2P upload默认关闭，只有用户明确开启后才上传，并更新隐私说明。
- SDK错误码包含quota、地区限制和copyright blocking，因此必须保留原下载器fallback。[迅雷错误码](https://open.xunlei.com/doc?doc=error_code)
- CurseForge项目具有单独的第三方distribution开关，不能绕过。[CurseForge Distribution Toggle](https://support.curseforge.com/support/solutions/articles/9000207877)
- Modrinth允许应用通过API下载内容，但仍要求遵守第三方权利和平台条款。[Modrinth Terms](https://modrinth.com/legal/terms)
- 迅雷协议限制通用文件分发、账号/token共享等行为。把第三方Mod加入P2P分发前，应先让迅雷确认这个launcher场景是否获准。[迅雷开放平台服务协议](https://console.open-xunlei.com/clause/service-agreement)

我的建议是：**先对公开、无header且≥16MiB的Modrinth/GitHub资源做可关闭的试点；暂时不要用于CurseForge和RDI整合包。**后续如果迅雷Java SDK加入header支持，或者RDI改用短期signed URL，再评估整合包加速。
